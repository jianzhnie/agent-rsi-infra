# Agent 协作与任务契约

本设计按 [RSI 设计](RSI_DESIGN.md) 落地训练与推理调研中的上下文加载、专项技能、模块边界和证据驱动工作方式。它定义协作协议，不是自动调度器，也不启用新的执行权限。

## 主流程保留的职责

主流程明确用户目标、目标仓库、范围与验收条件，读取任务材料后选择适用 Skill；只有当前任务和运行环境允许时才委派。角色选择服务于独立子任务，普通修改无需为分工而拆分。

业务代码、共享规范与角色正文各有唯一来源。子任务中发现规则缺陷时返回证据和建议，由主流程审查后修改；不把日志、模型猜测或一次故障自动写成永久指令。

## 交接内容

| 交接项 | 必须明确的信息 |
| --- | --- |
| 目标 | 问题、预期行为、范围外事项和完成条件 |
| 上下文 | 代码 revision、相关实现、已有失败/基线、目标项目指令 |
| 执行范围 | 分析还是修改、可写文件、允许的命令/服务/设备、资源预算 |
| 任务契约 | 输入输出、数值与兼容要求、涉及的训练/rollout/服务阶段 |
| 返回证据 | 文件位置、实际命令、结果、产物位置、未执行项与限制 |

未提供设备或允许的在线操作时，角色先完成代码和已有产物分析，不默认安装、下载模型或启动服务。必要权限以用户已授予范围为准，不因每次交接重复请求确认。

## 现有角色与工作流

| 任务 | 入口 | 返回结果与边界 |
| --- | --- | --- |
| 错误、失败或状态异常 | [debugger](../.agents/agents/debugger.md) | 复现、首个异常、根因与范围内修复；无法复现时明确缺失条件 |
| 延迟、吞吐或资源退化 | [performance-analyzer](../.agents/agents/performance-analyzer.md) | 实测瓶颈、假设、建议和受影响配置；默认分析，不以预测代替收益 |
| 训练、RL、推理行为变更 | [training-inference-change](../.agents/skills/training-inference-change/SKILL.md) | 主流程使用的执行方法，按任务读取参考，不额外创建平行规范 |
| 独立审查 | [code-reviewer](../.agents/skills/code-reviewer/SKILL.md) | 只读、可定位的问题与覆盖限制，不代替作者实施或批准 |

Claude 和 Codex 适配均由共享角色生成。客户端原生工具名与 sandbox 放适配层；共享角色不绑定模型、客户端权限字段或本地机器路径。配置文件生成正确不等于客户端已经加载。

## 验证与决策分离

实施者说明改动和验证，审查者按证据复核关键契约。二者共享输入和事实来源，但分别报告实际覆盖，不能把“另一角色说通过”当作测试执行记录。

训练任务分别交付数值、并行/恢复与模型行为；RL 任务检查样本、权重版本与异步边界；推理任务检查请求、调度、缓存和多阶段生命周期。性能数据另行报告。主流程综合结果决定是否完成，不因一个子任务通过而宣称整条链路已验证。

遇到以下情况返回主流程：需求不能确定产品语义、修改越过约定文件/模块边界、设备或环境不足以验证、不同证据相互矛盾。返回已完成工作、阻塞点和最小下一步，不擅自扩大范围或掩盖覆盖缺口。

## 来源与适用边界

方法来源为[训练框架调研](research/training-frameworks-agent-engineering.md)中的 Megatron-LM、verl、slime、vime 及[推理框架调研](research/inference-frameworks-agent-engineering.md)中的 vLLM、SGLang 与 Omni 项目。本文为本仓库的协作设计，不声称这些项目都提供相同 Agent 运行时。逐项目迁移与未采用政策见[迁移记录](framework-practices.md)。
