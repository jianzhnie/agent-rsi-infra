# 工程实践标准

本文件定义本仓库采用的工程原则，执行流程见 [AGENTS.md](../AGENTS.md) 和 [贡献说明](../CONTRIBUTING.md)。用于其他 AI Infra 项目时，按其接口契约、工具链和支持范围适配，验证强度与改动影响相称。

## 协作与 Agent 配置

- AI 辅助生成的代码与配置须由人类提交者理解、审查、验证并负责。
- Agent 先读取任务材料与目标仓库指令，选择并加载适用 Skill，再分析代码和实施改动；排障时先核对失败证据。
- 多 Agent 与多客户端使用统一规则源；客户端适配不重复维护业务规范。
- 根级 `AGENTS.md` 保持精简，领域知识下沉到指南，可复用任务流程封装为 Skill。
- Agent 指令避免重复、冲突和无效规则；单次事故优先修代码、测试或 CI，不直接增加永久限制。
- Agent 配置、角色、Skills、Hooks 和权限适配自身也须经过 Review；检查适用范围、加载路径、执行权限及验证证据，不能将配置存在视为已生效。
- 开始贡献前检索相关 Issue 和 PR，避免重复实现；清理工作围绕明确问题组织，避免无实际收益的零散 busywork。
- 人类提交者逐项理解 AI 生成改动，说明 AI 参与范围，报告实际测试与评测结果及未验证项。
- 提交前自查完整变更，按需使用审查 Skill 和人工 Review 指南；自动检查通过不替代人工判断。

协作沟通与隐私要求见[贡献说明](../CONTRIBUTING.md#协作行为)，技术判断仍以代码、契约和验证证据为依据。

## 规范分层与客户端适配

| 机制 | 职责 |
| --- | --- |
| `AGENTS.md` | 通用工程约束、工作顺序和常用命令 |
| 领域指南 | 模型、训练、RL、推理、Kernel 与编译器的专项契约 |
| Skill | 可复用的多步骤任务流程及附属工具 |
| Hook / CI | 适合自动执行的检查与事件动作；真正的门禁需要可执行检查 |
| MCP | 外部工具与数据连接，访问范围由运行环境管理 |

一个规范源配合多个客户端入口。Claude Code 由 `CLAUDE.md` 引用共享指令；Codex 使用 `AGENTS.md`，专用适配放 `.codex/`。采用 Cursor 的目标项目可按所用版本使用 `AGENTS.md` 或 `.cursor/rules/*.mdc`；本仓库未提供 Cursor 专用配置。不同客户端的加载、信任和权限机制分别验证，不因共享正文就假定能力一致。

## 实现与文档

- Python、C/C++、CUDA、构建系统与编译器 API 分层治理，沿用目标项目工具和接口契约。Python 命名、缩进和依赖选择见[代码规范](../CONTRIBUTING.md#代码规范与依赖)。
- 生成文件先查模板与生成命令，修改源文件后重新生成，不手工修改生成结果；本仓库角色适配由 `scripts/sync_agents.py` 从共享定义生成。
- 文档中的 CLI 参数、环境变量默认值和实际行为，依据对应版本的源码、配置定义或官方资料核对；记录来源及版本，对冲突或未核实内容明确说明。
- 沿用项目选定的 Python 解释器与依赖管理方式，可使用 uv 和项目虚拟环境；隔离实验依赖，缺少工具时明确报告。

## 测试与验证

- 测试明确模块职责、输入输出契约、可观察行为和能捕获的失败场景，在能发现目标故障的最低成本层级验证。
- 按影响覆盖算子行为、边界输入、设备差异和真实回归，不以实现镜像或无法触发故障的压力循环代替有效测试。
- 分布式测试记录设备数量、节点数、并行策略和启动命令；Checkpoint、数据并行、张量并行及流水线改动需验证受影响的恢复与通信契约。
- 修改模型数值或生成行为时提供相应模型评估；配置、加载或接口变化按实际影响选择验证。大型训练任务区分快速检查与昂贵的完整验证。
- 多硬件 Target 的数值实现或共享计算路径变化，验证受影响目标的数值正确性，说明 reference、dtype 和容差；非数值路径验证相应接口与运行契约。缺少硬件时列出覆盖缺口，不宣称支持已验证。
- 正确性测试与性能 benchmark 分离，结果分别呈现；Kernel benchmark 放在专门目录。
- 涉及 Kernel 性能路径的 PR 提供可复现的性能数据：硬件、版本、输入规模、计时边界、缓存条件、绝对前后耗时与波动。不影响性能路径的接口或文档改动无需 benchmark；无设备时报告未验证，不能仅凭代码宣称加速。

## 训练、RL 与 Kernel 的 PR 要求

训练框架的验收不能止于 Python 风格检查。按受影响路径说明正确性、复现条件、兼容性、性能与硬件覆盖；数值或状态变化需验证训练行为、checkpoint 恢复和相关并行组合。

- **RL Infra**：明确训练与 rollout 的模块、协议和状态边界；按影响验证采样、logprob、权重同步及异步流程。记录复现所需的模型、数据、随机设置和运行配置，说明 GPU/NPU 差异。优化以实测收益为依据，不引入缺少实际需求的大型抽象。
- **训练 Kernel**：独立报告算子 correctness、模型级训练或 convergence 对照、性能 benchmark。涉及训练数值时，不能用算子单测替代模型行为验证；性能对照固定环境和负载，报告重复测量与波动，不将未复现的单次数字作为收益依据。
- **项目贡献流程**：PR 是否使用草稿、fork、签名或特定来源声明，按目标项目当前要求执行，不转为本仓库统一政策。引用或迁移代码须保留来源与许可。
- **框架专用契约**：Megatron Core 的进程组显式传递等要求，只在目标版本和组件适用时检查；不能机械推广到其他训练或推理框架。

详细验证矩阵见 [AI Infra 工程实践](ai_infra_agent.md#validation)，复审与 CI 覆盖方法见 [贡献说明](../CONTRIBUTING.md#pr-复审与验证证据)。

## 工具与检查

- Python 使用 Ruff 管理格式与 lint，pytest 组织测试。
- C/C++ 使用目标项目的 clang-format 配置；必要时用专项审计脚本辅助检查 API 风格与契约。
- pre-commit 统一执行已配置的提交检查，相关回归与设备验证按影响补充。
