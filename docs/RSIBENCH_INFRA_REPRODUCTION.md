# RSIBench-Infra paper-aligned reproduction framework

This branch implements a reproducible protocol and evaluator reference, not the paper authors' production runtime or a reproduction of their reported agent results. The public project page announced the code as coming soon. This repository reconstructs the published task matrix, verifier contracts and scoring semantics; it does not claim access to private task packages.

## Architecture and trust boundaries

The paper separates three jobs:

1. **Agent Job** starts from a pinned runnable baseline and may modify engine, kernel and instruction layers. Its deliverable is a compressed OCI filesystem layer containing an executable root launch.sh.
2. **Serve/Train Job** starts from the same clean baseline digest and applies the exact same layer digest on every rank.
3. **Benchmark Job** runs a trusted evaluator image that does not contain or mount the candidate layer. It communicates with the separately deployed candidate service through its service interface, validates task quality, then measures end-to-end throughput.

The code validates the 20-task catalog, the five-task single-H20 Lite Set, OCI archive structure, per-rank layer identity, benchmark isolation assertions, task quality measurements, paper scoring and exact eligible-task aggregation. It does not create containers, launch models, schedule accelerators or independently inspect runtime namespaces. A production scheduler must emit the run manifest from trusted container/runtime observations rather than accept candidate-authored claims.

## Install and commands

```bash
python -m pip install -e '.[dev]'
python scripts/rsibench_infra.py catalog benchmarks/rsibench_infra/tasks.json --lite-set benchmarks/rsibench_infra/lite_set.json
python scripts/rsibench_infra.py inspect-submission submit_oci.tar.gz
python scripts/rsibench_infra.py verify-quality glm_52_744b_sglang quality.json --catalog benchmarks/rsibench_infra/tasks.json --gates benchmarks/rsibench_infra/quality_gates.json
python scripts/rsibench_infra.py validate-run run-manifest.json --catalog benchmarks/rsibench_infra/tasks.json
python scripts/rsibench_infra.py score result.json --output scored.json
python scripts/rsibench_infra.py aggregate aggregate.json --output summary.json
```

For LongBench v2, pass --acceptance-accuracy from a separately versioned baseline calibration. The paper describes task-specific acceptance but does not publish a universal numeric threshold; inventing one would invalidate a faithful comparison.

## Scoring

For a formally completed, compliant run that passes deployment, quality and performance gates:

\[
  \mathrm{speedup}=\frac{P_{\mathrm{candidate}}}{P_{\mathrm{baseline}}}
\]

A valid slowdown remains below 1. A formally evaluated failure receives zero; work that was never run is unscored and excluded from the eligible task set. Faster Rate counts strict speedups greater than 1.10x. The SOL score uses baseline throughput \(b\), candidate throughput \(p\), and analytical SOL throughput \(s\):

\[
S=\frac{1/b-1/s}{(1/p-1/s)+(1/b-1/s)},\quad \mathrm{SOLScore}\in[0,1].
\]

The aggregation API requires exactly the eligible task IDs and retains formal zeros; it does not silently discard failures. The aggregation function is scoped to exactly one agent configuration and one result per eligible task; it never selects the best of repeated attempts. The paper's 86/130 Faster results (66.2%) are cited as paper results only and are not generated by this code.

## Task-specific quality checks

quality_gates.json maps each task to a quality gate. The 20-task inventory preserves Table 1 workload cardinalities; Table 3's dagger-marked GLM-5.2, GLM-5.3-Flash, Kimi K3 and Nemotron 3 Ultra baseline/SOL values are tagged as prefix-average extrapolations rather than direct measurements. See tasks.json for each task's reference kind.

The paper's seven agent configurations, editor surfaces, eight-hour per-task budget, max reasoning setting, 1M-token context limit and Claude's ten API-safety not-run exclusions are recorded in [agent_configurations.json](../benchmarks/rsibench_infra/agent_configurations.json). The not-run exclusions are not formal failures and must not enter that configuration's denominator. The evaluator checks GSM8K accuracy, task-calibrated LongBench subsets, MMMU reference accuracy, video/audio metadata and reference metrics, every LingBot chunk's frame count/shape/event and pixel metrics, frozen robot action shapes and errors, speech WER, and training loss/gradient replay. Training evidence must pass identity/admission/negative-control checks and show ordered, finite updates with unchanged masks, input counts and optimizer-update counts. VLM-GRPO checks the five normalized-error signal families plus nonnegative actor/reference forward discrepancies, and preserves inconclusive outcomes without automatic retry. These functions accept measurements from an independent trusted verifier: they do not load datasets, model weights, video/audio assets, or reference traces, and they do not establish that a candidate did not tamper with evidence.

## OCI submission checks

inspect-submission reads the compressed archive without extraction or execution. It rejects unsafe paths, duplicate entries, links/devices/FIFOs, excessive uncompressed size and entry counts, and requires an executable root launch.sh. It reports the OCI descriptor digest (compressed archive SHA-256) and uncompressed tar diff ID. This structural check is not a malware scan, provenance attestation, image-layer apply implementation, or runtime isolation guarantee.

## Reproduction gap

| Paper element | Implemented here | Still required for a full reproduction |
|---|---|---|
| 20 production tasks / 5-task Lite Set | Task metadata, topologies, published baseline and SOL rates | Official launch recipes, container images, model weights, tokenizers, traces, datasets and oracle assets |
| Task quality verifiers | Versioned mapping and measurement-level gate logic | Dataset loaders, reference generation, calibrated LongBench thresholds, trusted verifier images |
| OCI submission | Structural parser, descriptor digest and diff ID | Author-compatible layer packer, whiteout semantics, provenance and clean image apply |
| Multi-rank deployment | Declarative run contract checks exact digest on every rank | Real cluster scheduler, image pull/apply, mount namespace and rank attestation |
| Independent benchmark job | Contract prevents candidate layer/mounts in the declared benchmark job | Candidate-proof executor, benchmark clients, evaluator isolation and runtime audit |
| Agent experiment | Task/result protocol | Seven agent configurations, fixed harness versions, 8-hour budget/accounting, trajectories and retries |
| Agent configurations | Seven configurations, IDE surfaces, budget, context policy and not-run exclusions | Exact provider/model snapshots, API billing and reproducible trajectory exports |
| Published results | Scoring formulas and aggregate logic | Actual 20-task runs on the specified GPU/NPU clusters and comparison against paper tables |

The paper uses up to 32 accelerators and multiple nodes. Running its full task suite requires model/data assets, the corresponding accelerator types and independent execution infrastructure. This branch must not be described as a complete reproduction of experimental results.

## Safety

Never execute candidate launch scripts in the benchmark evaluator. Keep evaluator code read-only and candidate-inaccessible, use fresh job workspaces, pin all baseline/workload/verifier/hardware revisions, and store raw logs and measurements immutably. A JSON manifest is an assertion until corroborated by the site runner. Neither the OCI digest nor a checksum of supplied evidence is a signature.
