# AI Infra 变更验证

## 确定契约

先读取目标仓库的指令、任务依据、实现和已有测试，说明预期行为与受影响接口。修改 Kernel 前检索同一计算契约的已有实现和真实调用形状，决定复用、迁移还是新增。

本仓库的调研是参考资料，不替代目标仓库的当前实现、贡献政策和测试命令；不要复制某项目的签名、PR 或环境要求到所有项目。

## 选择验证

按 [验证矩阵](references/validation.md) 只选择受影响的行。先运行能暴露问题的最低成本检查，再按实际影响补充模型、分布式与硬件验证。

- 数值变化明确 reference、容差、dtype、shape 与边界；涉及训练时考虑梯度和多步行为。
- 状态变化检查保存恢复、生命周期、取消或失败传播。
- 配置与公共 API 变化检查兼容性和生成契约；按目标脚本更新生成文件。
- 性能变化固定 baseline/candidate、环境和负载，保存原始数据；未测量的收益只作为假设。
- 无设备、模型或依赖时完成可执行检查，列出缺少的验证及原因，不用 CPU 导入或静态阅读替代设备测试。

## 交付与持续改进

报告：变更和契约、代码版本、真实命令与结果、未运行项、日志位置。性能结果另附环境、输入、预热、重复次数、统计口径与回退项。

遇到可重复的缺陷，优先修正实现、脚本或回归测试。只有对后续任务仍有用的仓库特有知识才进入规则或 Skill；写明依据和适用范围，由贡献者审查，不自动改写指令或扩大权限。
