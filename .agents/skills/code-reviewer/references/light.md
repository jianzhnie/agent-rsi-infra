# 轻量审查

快速发现容易遗漏、修复代价高的问题。先读 diff、相关上下文、已有测试和目标仓库规则；不要将快速检查扩展为全面设计讨论。

## 检查范围

- 明确的逻辑错误、崩溃、数据损坏、安全问题或破坏既有接口的变化。
- 改动影响的文档是否仍正确，尤其是参数、默认值、命令与实际行为。
- 新行为或 Bug 修复是否有能防止该故障的验证；先查看现有测试，只建议必要的代表性用例。
- 新参数或配置是否接入真正的执行路径，避免声明存在但功能不起作用。
- 目标项目中明确且未由工具执行的工程约束。针对 AI Infra 变更，查对应数值、状态、并发或硬件契约。

只在具体失败路径或明确契约支持时报告。无需为文档润色、可逆的小改动或配置默认值机械增加测试；不要求镜像实现的测试。

## 排除范围

不重复 lint/formatter 的格式意见，不报告个人命名偏好、无关重构或未测量的性能猜测。不把“可以加一个测试”本身列为问题；说明缺少的验证能防止什么真实回归。

Megatron 的进程组迁移规则、Kernel 确定性测试目录和注册清单不是通用要求。目标项目确有这些约束时再检查，不能要求其他仓库创建同样目录。

## 交付

仅输出经过核实、按影响排序的问题；每项给出位置、触发条件、后果与最小修复方向。没有可确认问题时直说，并注明重要的未覆盖范围。不执行 GitHub 评论或批准操作。
