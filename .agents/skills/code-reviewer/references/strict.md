# 严格审查

用于用户明确要求的深入审查。读取重要改动的完整上下文，追踪调用者、数据流、状态与测试；大 diff 可按风险安排顺序，但必须说明未覆盖部分。

## 按影响追踪

| 方面 | 检查内容 |
| --- | --- |
| 实现与数值 | dtype 转换和累积、归约维度与归一化、loss scaling、norm/attention、优化器、梯度裁剪、权重绑定、MoE 路由是否符合算法契约 |
| 分布式 | TP/PP/DP/SP/CP/EP 的分片、通信、同步、microbatch 与梯度累积是否一致；是否可能死锁或静默产生错误结果 |
| 状态与恢复 | checkpoint 键、优化器状态、RNG、保存加载和恢复能否维持预期语义；取消或异常后资源能否释放 |
| 性能 | 真实热点中的 CPU/GPU 同步、额外复制、通信和 Kernel launch；图捕获、重编译与显存变化是否有实际依据 |
| 兼容性 | API 签名、配置默认值、checkpoint、模型层序或初始化变化是否需要迁移、弃用或兼容方案 |
| 加速器与可选依赖 | 共享路径是否绕过目标项目的设备抽象；新增抽象方法是否使未修改的实现无法实例化；设备或可选包缺失时，导入与构建是否仍符合支持契约 |
| 新接口是否生效 | 参数、字段和局部变量是否有可达的使用路径；仅声明、注释或 `_ = value` 不代表功能已接通 |
| 验证有效性 | 测试是否覆盖改变的行为，是否确实能失败；reference、容差与性能对照是否匹配目标版本和环境 |

这些是调查方向，不是统一的实现方案。是否上转 FP32、融合算子、增加检查或保留预留参数，都需要根据目标算法、协议和硬件判断。

## 判断标准

- 声称数值或性能有问题时，给出调用路径、数据或复现依据。只看到“可能更快”的写法不构成性能缺陷。
- 审查有意保留的回调签名、兼容层和协议参数时，先核对契约，不机械判为无用参数。
- 测试建议与风险相称。优先复用测试和小输入；只有问题依赖规模、设备或分布式拓扑时才要求对应资源。
- 可维护性建议必须解释实际成本或故障，不能只根据函数行数、命名偏好或抽象风格提出重构。
- 考虑作者的设计依据和已知限制；深入追踪后不成立的问题直接删除，不用模糊措辞保留。
- 不要求新增整套安全或性能审计，除非改动本身触及对应边界或用户明确要求。

测试与注释的判断依据见[贡献要求](../../../../CONTRIBUTING.md#测试与注释审查)。检查断言保护的独立契约及并发复现是否有效；不因实现简单就删除注册完整性或负分支用例，也不在清理注释时丢失跨文件约束。

## 长期资源复用

改动扩大资源复用范围或延长生命周期时，检查所有对象、层、设备与 rank 的聚合保留量，而非只看单次分配。验证负载或 shape 改变、重新规划和失败清理后资源能否释放，并记录应用可用显存余量。API 预热或局部 benchmark 不能证明完整服务启动、模型加载和 KV Cache 容量仍然满足要求。

## 共享执行路径

- 扩展设备接口时检查所有受影响实现，默认实现也需符合其支持契约。仅在项目存在设备抽象时要求沿用它；CUDA 专用代码可直接使用 CUDA API，不推广 DeepSpeed 的调用禁令。
- 通信检查以参与进程组为边界，核对调用顺序和各 collective 的形状、dtype 契约；all-gather/reduce-scatter 等操作按各自协议判断，不机械要求所有输入形状相同。关注依赖 rank 局部状态的分支、提前返回与异常退出。
- 异步拷贝、offload 和预取同时核对 stream/event 依赖及 allocator 生命周期；等待数据就绪与防止 buffer 提前复用是不同问题，不能假设 `record_stream` 本身建立执行依赖。
- 共享格式、打包顺序或命名机制的副本若必须同步才能正确，检查是否有统一事实来源或一致性验证。不能仅因代码相似就要求抽象，也不能忽略耦合副本的漂移。
- 设备同步、持久 buffer 和额外分配的性能判断需结合热点与测量，比较收益时同时记录峰值内存。优化一组配置时说明受影响的精度、分片、offload 与并行组合。

复审与 CI 覆盖核对见[贡献要求](../../../../CONTRIBUTING.md#pr-复审与验证证据)，区分“已有 workflow”和“当前 head 实际执行了受影响路径”。

## Megatron 专项边界

只有目标是 Megatron Core 且相关版本仍要求时，才检查新增全局进程组读取是否应改为显式传入 `ProcessGroupCollection` / `ProcessGroup`。初始化、配置、测试及明确迁移回退按目标规则处理，不自动扩展到训练循环。

只有目标仓库要求 bit-exact 确定性门禁时，才检查相应测试和 manifest。普通数值一致性应按算子容差与算法契约验证，不能强行等同于逐位一致。

## 交付

按实际影响排序，区分阻断缺陷与非阻断问题，不以发现数量或信心高低决定严重度。每项说明位置、触发条件、后果和修复方向；同时列出未执行的关键验证。审查结论返回用户，不自动发布或批准 PR。
