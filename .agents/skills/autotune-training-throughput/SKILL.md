# 训练吞吐调优

## 适用范围

用于已有训练实现的吞吐诊断与候选对比。先读 [来源与适配边界](UPSTREAM.md)。训练由目标项目的现有入口执行；本 Skill 不提供任务运行器。

## 输入与前置条件

固定代码与框架版本、模型、数据及其 hash、全局 batch、序列长度、精度、设备数量与拓扑。明确可改参数、测量窗口、预算和验收阈值。不要把上游默认的 20 步、5–19 窗口或固定长度数据当作通用标准。

## 工作流程

1. 阅读目标项目指令和训练入口，选择 stacks/ 下适用的框架参考，核对当前版本。
2. 重复测量基线，记录预热、完整 update 耗时和波动；保持数据与训练语义不变。
3. 分析本地日志或 trace，每次提出有证据的候选；通过目标项目入口执行已授权实验。
4. 用相同协议复测候选，检查完整窗口、数值结果与受影响行为。诊断采集与正式计时分开。
5. 保留成功和失败的原始证据，人工审查后再采用候选。

## 验证

从仓库根目录运行 `python3 -m autotuner.profile_analyzer --profile-dir <dir> --json`，分析已有 trace；依赖和边界见 [工具说明](../../../autotuner/README.md)。日志吞吐统计、基线校准和数值测试使用目标项目的现有工具。

首步 loss 和参数分类不能替代梯度、参数更新、checkpoint 恢复或收敛验证。没有设备时明确列出未运行项，不宣称吞吐收益。

## 交付物

提供基线与候选配置、实际命令、代码与数据版本、设备信息、原始日志、测量窗口、重复结果、失败原因及未验证项。实验记录应关联原始产物，并明确证据的验证范围。
